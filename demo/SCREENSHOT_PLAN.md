## Redaction requirements

Prohibited: client and product names; logos that reveal identity; live deployment, Sheet and repository URLs; IDs embedded in query strings; credentials; personal names and contact details; real opportunity titles, organizations, countries and keywords; ToR contents; client library text and filenames; private paths; source code; Git history; logs and traces; account avatars; browser history, recent files and notifications.

Prefer complete synthetic replacement to redaction. If an authorized screenshot ever requires redaction, apply opaque replacement to the raster, flatten the image and inspect the exported pixels. Blur alone is insufficient. Remove metadata and inspect filenames, alt text, captions, link targets and thumbnail previews. A sanitized basename can still identify a client document.

## Per-image approval gate

Record filename, capture date, synthetic fixture used, reviewer and result for each image. PASS requires all visible text, metadata, background pixels and captions to be checked. Any unknown origin or unresolved redaction is FAIL pending owner review. Recheck the final composite after cropping or layout changes. Do not publish any screenshot based solely on approval of this plan.
